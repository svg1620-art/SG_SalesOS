## 1. Что это за система

**SG_SalesOS** — операционная система управления качеством и эффективностью
продаж для ServiceGuru. Состоит из **двух модулей**, работающих на одной базе
и одном деплое:

1. **ОКК (отдел контроля качества) + коучинг** — анализ звонков отдела продаж.
   Звонок → авто-транскрибация с разделением «Менеджер/Клиент» → оценка по
   чек-листу (балл + зона 🟢/🟡/🔴) → рекомендации по навыкам и упущенные
   моменты → ежедневная AI-сводка для РОПа.

2. **«Операционный пульт» (Ops Metrics)** — операционные метрики, воронка,
   конверсии, окупаемость менеджеров, планы, геймификация (миссии/XP). Данные
   тянутся из amoCRM (события, этапы воронки, сделки).

**Ключевой принцип доступа:** РОП (admin) видит всё и всех; менеджер (manager)
видит только себя.

## 2. Стек и инфраструктура

| Слой | Технология |
|---|---|
| Backend | Python 3.11+, Flask + Jinja2 + HTMX (без React) |
| БД | PostgreSQL + SQLAlchemy, миграции Flask-Migrate (Alembic) |
| Фон | APScheduler (обработка звонков, синхронизация, сводки, миссии) |
| Графики | Chart.js |
| ИИ-анализ/сводки | Anthropic Claude (модель из env) |
| Транскрибация | OpenAI `gpt-4o-transcribe` (есть альтернативы: Deepgram, DeepSeek) |
| Auth | Flask-Login, 2 роли: `admin`, `manager` |
| Деплой | **Railway, регион EU**, Volume на `/data` |

**Жёсткие правила окружения (проверено на практике):**
- **Регион Railway — только EU.** Из US/РФ нет доступа к Anthropic API.
- Переменные окружения добавлять **по одной**, **без кавычек** (копипаст блоком
  склеивает значения).
- `DATABASE_URL` — следить за невидимой кириллицей (был баг).
- Файловая система эфемерна между деплоями. **Аудиозаписи — только в Volume
  `/data`** (`AUDIO_DIR=/data`).

Пиннинг зависимостей критичен: `openai>=1.57.4`, `httpx[socks]==0.27.2`
(связка `openai==1.51.2`+`httpx==0.28.0` падает). См. `requirements.txt`.

## 4. Данные: откуда берутся

### amoCRM (основной источник)
- **Звонки** — из примечаний `call_in`/`call_out` (контакты + сделки).
- **Сообщения, смены этапов** — из `/api/v4/events`.
- **Сделки** — из `/api/v4/leads`. Успех = статус **142**, проигрыш = **143**
  (системные ID; названия в интерфейсе amoCRM могут быть любыми).
- **Авторизация:** долгосрочный Bearer-токен (задаётся в Настройках). OAuth-поля
  тоже поддержаны.
- **Привязка к менеджеру:** `responsible_user_id` в amoCRM → `User.amo_user_id`.
  Если не сопоставлено — выручка/активность «висят» непривязанными. Лечится:
  Настройки → «Синхронизировать пользователей».

### Записи звонков и ПРОКСИ (важно!)
Записи лежат на стороне Мегафона (`megapbx.ru`), который **блокирует
иностранные IP**. Сервер на Railway EU при прямом скачивании ловит
`ConnectTimeout`. Поэтому скачивание записей идёт через **российский IP-прокси**.

- **Где задаётся:** Настройки → поле «Прокси для скачивания записей (RU-IP)»
  (или env `RECORDING_PROXY`).
- **Формат:** `http://ЛОГИН:ПАРОЛЬ@IP:ПОРТ`
- **Какой покупать:** IPv4, страна Russia, выделенный (не shared), авторизация
  по логину/паролю (не по IP — у Railway исходящий IP непостоянный).
- Прокси нужен **только** для загрузки файлов записей, на API amoCRM не влияет.

### Диаризация
Записи Мегафон ВАТС — честное стерео (стороны на разных каналах). Режем на два
моно, транскрибируем раздельно, склеиваем по таймингам → «Менеджер/Клиент».
Канал менеджера — флаг на аккаунт. Фолбэк для моно — разметка Claude по смыслу.

## 5. Как считаются оценки и метрики

### Зоны качества звонка (ОКК)
- Каждый критерий Claude оценивает 0–10. Итог = Σ(score/10 × weight), веса в
  сумме 100.
- Пороги (редактируются): 🟢 ≥80, 🟡 60–79, 🔴 <60.
- **Критичные критерии:** если критичный критерий = 0/10 — зона не выше 🟡, даже
  при сумме ≥80.

### Звонки (дашборд `/ops/calls`) — три уровня
- **Попытка** — набрали номер (усилие менеджера).
- **Дозвон** — клиент снял трубку (`duration > 0`).
- **Разговор** — состоялся разговор ≥ порога (по умолчанию 30 сек).
- % дозвона = дозвоны/попытки; % разговора = разговоры/дозвоны.
- Если недозвоны «не доезжают» (телефония не логирует неотвеченные) — это видно
  на `/ops/validation`, раздел «Недозвоны».

### Первая выручка и окупаемость
- **Первая выручка** = первый оплаченный заказ клиента (`client_key` =
  `company:<id>` либо `contact:<id>`). Повторные оплаты не считаются.
  Хранится флагом `is_first_revenue` на `Deal`.
- **Окупаемость** = маржа (первая выручка) / полные затраты (свои + доля РОПа).
  🟢 ≥1.0, 🟡 0.8–1.0, 🔴 <0.8. В период адаптации новичка пороги снижены.
- **Авто-бонус:** план выполнен → ставка `bonus_rate_plan_met` (деф. 9%);
  ≥ минимума — `bonus_rate_below` (деф. 6%); ниже минимума — 0. База — первая
  выручка. Проставляется в `bonus_paid` автоматически.
- Если на `/ops/payback` «0.00» или «—» — на странице есть жёлтый баннер с
  точной причиной (нет затрат / нет сделок / не привязано к менеджеру).

### Геймификация (миссии, этап 5)
- Дневная миссия генерируется «обратной воронкой» от остатка плана → цели по
  метрикам с тирами 🥉/🥈/🥇.
- Уровни 1–3 (Ритм → Воронка → Результат), серии дней + заморозки, личные
  рекорды, командный квест недели.
- XP в едином журнале `xp_ledger` (идемпотентно, анти-накрутка: cap звонков/
  сообщений на контакт, quality gate на Gold).

## 8. Деплой и эксплуатация

### Деплой (Railway EU)
1. Проект в регионе **EU** + PostgreSQL + Volume на `/data`.
2. Переменные окружения — по одной, без кавычек.
3. Миграции применяются автоматически при старте (или `flask db upgrade`).
4. Админ создаётся из `ADMIN_EMAIL`/`ADMIN_PASSWORD` (`SEED_ADMIN_ON_START`).

Подробно — `docs/DEPLOYMENT.md`.

### Фоновые задачи (APScheduler)
- Опрос amoCRM (звонки + сделки) — каждые `POLL_INTERVAL_MIN`.
- Синхронизация Ops-событий + пересчёт метрик за сегодня — каждые N минут.
- Пересчёт за вчера + финализация миссий — 00:30.
- Генерация миссий — 06:00.
- Дневная AI-сводка — в `DIGEST_HOUR`; Telegram-пульс — в `TELEGRAM_HOUR`.

### Типовые проблемы (runbook)
| Симптом | Причина / решение |
|---|---|
| Запись не качается (ConnectTimeout) | Не задан/неверен `RECORDING_PROXY`. См. §4. |
| Выручка «одной суммой», не по менеджерам | Не сопоставлены `amo_user_id`. Настройки → Синхронизировать пользователей → Пересобрать сделки. |
| На `/ops/payback` нули/прочерки | Читать жёлтый баннер — он называет причину. |
| Лидерборд/пульт пусто | Нет сделок за месяц, либо не нажата «Пересчитать первую выручку». |
| Нет доступа к Anthropic | Регион Railway не EU. |
| Звонок завис | `Call.status=failed`, причина в `Call.error`; «Переобработать». |

Полный runbook — `docs/RUNBOOK.md`.

## 9. Статус по этапам

**Базовый модуль ОКК:** этапы 1–9 готовы (каркас, чек-листы, пайплайн
транскрибации+анализа, карточка звонка, агрегация диалогов, дашборд РОПа,
кабинет менеджера, интеграция amoCRM, дневная AI-сводка).

**Модуль «Операционный пульт»:** готовы **этапы 1–5**:
1. Сбор событий, маппинг воронки, `/ops/validation`.
2. Движок метрик, «Мой день», планы/отсутствия, hire_date.
3. Пульт РОПа, воронки/конверсии, тепловая карта, прогноз плана.
4. Окупаемость + затраты, первая выручка, доля РОПа, факторная диагностика,
   авто-бонус, деактивация.
5. Миссии и геймификация (миссии/XP/тиры/уровни/серии/рекорды/квест),
   дашборд `/ops/calls`, диагностика недозвонов.
