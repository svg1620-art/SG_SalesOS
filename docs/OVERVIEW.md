# SG_SalesOS — Обзор проекта (про что, связи, доступы, логика, отчёты)

Короткий функциональный обзор системы: что она делает, с чем связана, кто что видит, как устроена логика и какие даёт отчёты. Технические детали — в соседних файлах `docs/` (ARCHITECTURE, DATA_MODEL, AI_PROVIDERS, AMOCRM, CONFIGURATION, DEPLOYMENT, RUNBOOK).

## 1. Про что проект

**SG_SalesOS** — операционная система контроля качества продаж для **ServiceGuru**: ОКК (отдел контроля качества) + коучинг менеджеров + ежедневный AI‑агент‑сводка для РОПа.

**Задача:** каждый звонок отдела продаж автоматически превратить в объективную оценку качества и подсказки, что улучшить — без ручного прослушивания сотен записей.

**Как это выглядит для пользователя:**
- Звонок попадает в систему (из amoCRM автоматически или ручной загрузкой).
- Система его расшифровывает (с разделением «Менеджер / Клиент»), оценивает по чек‑листу и выдаёт **балл 0–100 + зону 🟢/🟡/🔴**, рекомендации по навыкам и список упущенных моментов с цитатами.
- **РОП** видит всю команду на дашборде; **менеджер** — только себя.
- Раз в день формируется AI‑сводка «на что обратить внимание» и уходит Telegram‑пульс.
- Из amoCRM тянутся закрытые сделки → **лидерборд по выручке с геймификацией (XP)**.

**Кому полезно:** РОП (контроль и приоритеты), менеджер (персональный коучинг), собственник (прозрачность качества и выручки).

## 2. Связи (интеграции и связи данных)

### Внешние системы
| Система | Роль | Направление |
|---|---|---|
| **amoCRM** (API v4, долгосрочный токен) | источник звонков и сделок, привязка менеджеров/клиентов | чтение (+ запись примечаний по запросу) |
| **OpenAI** `gpt-4o-transcribe` / **Deepgram** `nova-2` | транскрибация (STT) — выбор провайдера в настройках | исходящие запросы |
| **Anthropic Claude** / **DeepSeek** | текстовый AI‑анализ — выбор провайдера в настройках | исходящие запросы |
| **Telegram Bot** | дневной пульс и поздравления с продажами | исходящие |
| **Телефония (Мегафон ВАТС)** | записи звонков (через ссылки amoCRM; РФ‑прокси при необходимости) | скачивание |

### Связи сущностей (внутри системы)
```
Отдел ──< Пользователь(менеджер) ──< Звонок >── Чек-лист ──< Критерий
                                      │   │ └──< Оценка по критерию
                                      │   ├──< Рекомендация
                                      │   └──< Упущенный момент
Клиент(телефон) ──< Диалог ──< Звонок        (диалог = все звонки одного клиента)
Сделка(amoCRM) ── связывается со Звонком по контакту/лиду (исход: won/lost)
```
- **Звонок → Клиент → Диалог**: звонки одного клиента (по нормализованному телефону `+7XXXXXXXXXX`) агрегируются в «Диалог» (счётчик, средний балл, тренд).
- **Звонок → Сделка**: по контакту amoCRM или по лиду определяется исход (успех/проигрыш) — для фильтра в «Звонках» и скоринга лида.
- **Менеджер ↔ amoCRM**: сопоставление по `amo_user_id` (↔ `responsible_user_id`), обычно проставляется «Синхронизировать пользователей» по email.

## 3. Доступы (роли и кто что видит)

Две роли (Flask‑Login): **`admin`** (РОП/владелец) и **`manager`**.

| Раздел | admin (РОП) | manager |
|---|---|---|
| Дашборд (DashBoard 📈) | вся команда, все отделы | — (у менеджера свой кабинет) |
| Кабинет менеджера | — | только свои звонки/тренд/рекомендации |
| Звонки (лента, фильтры, карточка) | все звонки | только свои |
| Диалоги | все | только свои |
| Leaderboard | да | да, если в «Отделе продаж» |
| Чек‑листы, Пользователи, Отделы, Настройки | да | нет |

**Логин:** деактивированный пользователь (снята «Учётка активна») войти не может.

**Увольнение сотрудника (оффбординг):** **не удалять**, а снять галочку «Учётка активна».
- История (звонки, диалоги, сделки) **сохраняется** — она привязана по `manager_id`.
- Сотрудник **исчезает из всех рейтингов** (дашборд, лидерборд по звонкам и по выручке) и из фильтров менеджеров; вход блокируется.
- Защита: нельзя деактивировать себя и последнего активного админа. Вернулся — снова поставить галочку.

**Секреты/доступы к внешним системам** задаются в «Настройках» (в БД, приоритет над переменными окружения) или через переменные Railway: токен amoCRM, ключи транскрибации/анализа, токен Telegram. Деталь — `docs/CONFIGURATION.md`.

## 4. Логика (как считается)

### Пайплайн звонка
`new → downloading → transcribing → analyzing → done` (при сбое — `failed` + текст ошибки). Обработка идёт в фоне ограниченным пулом воркеров; падение одного звонка не роняет остальные.

### Транскрибация и диаризация
Записи Мегафона — честное стерео (стороны на разных каналах). Система разделяет каналы → «Менеджер / Клиent» и собирает диалог по таймингам. Для моно роли размечает AI. Какой канал — менеджер, задаётся флагом звонка.

### Оценка и зоны
- Каждый критерий чек‑листа AI оценивает **0–10**.
- Итог: **Σ(score/10 × weight)**, веса в сумме = 100. Балл считает бэкенд (не доверяя числу от модели).
- Зоны (пороги редактируются): 🟢 ≥ 80, 🟡 60–79, 🔴 < 60.
- **Правило критичных критериев:** критичный критерий с 0/10 не даёт зелёную зону (капает в 🟡), даже если сумма ≥ 80.
- Какой чек‑лист применяется: явный на звонке → активный чек‑лист **отдела** менеджера → общий активный. То есть продажники оцениваются по чек‑листу продаж, развитие клиентов — по своему.

### Выручка, лидерборд, XP
- Из amoCRM импортируются закрытые сделки: выигрыш = статус **142**, проигрыш = **143** (метки могут быть переименованы, напр. «Оплата получена»).
- Лидерборд: рейтинг по **выручке за месяц** (по дате закрытия сделки), фильтр по выбранной воронке.
- **XP:** +50 за каждые 50 000 ₽ выручки за месяц. За свежие выигрыши — поздравление в Telegram.

### Скоринг лида (НейроGuru)
По первому разговору AI оценивает потенциал сделки (0–100, hot/warm/cold) и даёт рекомендацию — по запросу на карточке звонка.

## 5. Отчёты и выгрузки

| Отчёт | Где | Что показывает |
|---|---|---|
| **Дашборд (DashBoard 📈)** | админ | KPI за период, donut по зонам, карточки менеджеров (объём звонков, отклонение к прошлому периоду, разбивка по зонам, баланс «говорил/слушал», выполнение плана, вовлечённость), лидерборд по звонкам, список рекомендаций «следующего шага» |
| **Leaderboard** | админ + продажи | рейтинг по выручке за месяц + XP, 🏆 за первое место |
| **Кабинет менеджера** | manager | свои звонки, тренд балла, агрегированные рекомендации, «что улучшить» |
| **Карточка звонка** | по доступу | плеер, транскрибация‑диалог с подсветкой упущений, скоркарта (радар критериев + цитаты), рекомендации, саммери, скоринг лида, следующий шаг |
| **Диалоги** | по доступу | агрегаты по клиенту: число звонков, средний балл, последняя зона, тренд |
| **Дневная AI‑сводка** | админ (дашборд) | «на что обратить внимание» за день (по компании и по менеджеру) |
| **Telegram‑пульс** | получатели из настроек | ежедневная сводка по менеджерам + поздравления с продажами |
| **Выгрузки** | админ | звонки по фильтрам (CSV/TXT), все диалоги (CSV) |

**Период и фильтры** на дашборде/в звонках: даты, менеджер, отдел, зона, исход сделки (успех/закрыто). По умолчанию дашборд — за текущий день; «Звонки» — за 30 дней.
