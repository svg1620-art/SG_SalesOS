# SG_SalesOS — Пакет документации (handoff)

Этот каталог — комплект документов для передачи проекта новому сотруднику **без потери контекста**.
Проект: операционная система управления качеством продаж ServiceGuru (ОКК + коучинг + AI‑сводки).

## С чего начать (порядок чтения)

1. **[ONBOARDING.md](ONBOARDING.md)** — быстрый старт за 15 минут: что это, как поднять локально, куда смотреть.
2. **[PROJECT_DOCUMENTATION.md](PROJECT_DOCUMENTATION.md)** — полный обзор проекта (единый большой документ).
3. **[ARCHITECTURE.md](ARCHITECTURE.md)** — компоненты, поток обработки, карта модулей, модель потоков.
4. **[DATA_MODEL.md](DATA_MODEL.md)** — все таблицы, поля, связи, статусы, дедуп.
5. **[AI_PROVIDERS.md](AI_PROVIDERS.md)** — транскрибация (OpenAI/Deepgram) и анализ (Claude/DeepSeek), переключение.
6. **[AMOCRM.md](AMOCRM.md)** — интеграция amoCRM: звонки, сделки won/lost, лидерборд, связка.
7. **[CONFIGURATION.md](CONFIGURATION.md)** — переменные окружения и настройки из интерфейса.
8. **[DEPLOYMENT.md](DEPLOYMENT.md)** — Railway, локальная разработка, миграции, CLI.
9. **[RUNBOOK.md](RUNBOOK.md)** — эксплуатация: типовые задачи, диагностика, грабли и их решения.

## Кратко о состоянии

- Стек: Python 3.11 / Flask + Jinja2 + HTMX (без React), PostgreSQL + SQLAlchemy, APScheduler, Chart.js.
- AI: транскрибация **OpenAI `gpt-4o-transcribe`** или **Deepgram `nova-2`**; анализ **Anthropic Claude** или **DeepSeek** — оба провайдера переключаются в «Настройках».
- Интеграции: amoCRM (звонки + сделки), Telegram (пульс).
- Деплой: Railway, регион **EU**, Volume `/data`, gunicorn `--workers 1`.
- Рабочая ветка мержится в `main`; Railway деплоит из `main`.

## Как поддерживать документацию

При изменении схемы/конфига/пайплайна обновляйте соответствующий файл здесь и, при существенных изменениях, — `CLAUDE.md`. Документы описывают код на момент выгрузки; если разошлись с кодом — верить коду.
